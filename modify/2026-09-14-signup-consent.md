## 6. 화면을 떠났다 돌아왔을 때 동의 상태 유지 — sessionStorage 로 해결 (2026-09-14 갱신)

- **#38 의 인수 조건**: 상세(`/signup/consent/detail`)에서 돌아왔을 때 동의 상태가 유지된다.
- **처음 기록**: 상세 화면이 없어 확인할 방법이 없다며 #38 로 넘겼고, `signup/consent/layout.tsx` 에
  클라이언트 Context 를 두는 방법을 제안했다. **그 제안은 쓰지 않았다.**
- **왜 layout Context 가 아닌가**: A·D 통합 검증(2026-09-14)에서 브라우저로 실제 태워 보니
  **돌아오는 경로가 셋이고 그중 둘이 이 폴더 밖**이었다.

  | 경로 | 이동 방식 | layout Context 로 덮이나 |
  | --- | --- | --- |
  | `/signup/consent` → `/signup/consent/detail` → 뒤로 | `router.push` (`BackButton` 의 `backHref`) | O |
  | `/signup/consent` → `/privacy-policy` → 뒤로 | `router.back()` | **X** — 방침은 `src/app/` 루트 route |
  | `/signup/nickname` → 뒤로 | `router.push("/signup/consent")` | **X** — 닉네임도 layout 밖 |

  layout 이 언마운트되므로 Context 는 아래 두 경로를 덮지 못한다. 세 경로 모두에서 체크가 풀리는 것을
  실제로 확인했다(`true` → `false`).
- **실제로 한 것**: `ConsentForm.tsx` 한 파일에서 `sessionStorage` 에 동의 상태를 둔다. 세 경로를 모두 덮고
  탭을 닫으면 사라진다. 새 파일도, 공용 파일 수정도 없다.
  - 읽기는 **`useSyncExternalStore`** 다. 서버 스냅샷이 항상 `false` 라서 서버 HTML 과 hydration 이
    미동의 상태로 일치하고, 붙은 뒤에 저장된 값으로 다시 그려진다 — **hydration mismatch 가 없다.**
    처음에는 `useState` + `useEffect` 복원으로 짰는데 **ESLint `react-hooks/set-state-in-effect` 에 걸렸다.**
    규칙을 끄지 않고, 외부 저장소를 읽는 용도로 React 가 제공하는 이 훅으로 바꿨다.
  - `sessionStorage` 는 문자열 저장소이고 **`"false"` 도 truthy** 라 `Boolean(getItem(...))` 으로 읽으면
    해제 상태가 체크로 되살아난다. `=== "true"` 로만 복원한다.
  - **해제(false)도 저장한다.** 그래야 돌아왔을 때 해제 상태로 복원된다.
  - 읽기·쓰기 모두 `try/catch` 로 감싸고, **저장에 실패해도 화면 조작은 막지 않는다**(persistence 만 포기).
  - state updater 안에서 storage 를 건드리지 않는다 — 토글은 `writeAgreed(!agreed)` 한 줄이고
    저장 뒤 구독자에게 알리는 방식이라 updater 가 두 번 실행되는 상황과 무관하다.
- **범위 메모**: #38 인수 조건은 상세 왕복 하나지만, **방침·닉네임 왕복까지 함께 덮었다**(팀 확정 2026-09-14).
  세 경로가 같은 원인이고 같은 한 줄로 해결되기 때문이다.
- **남는 것**: 동의 여부·일시를 **서버에 저장**하는 것은 여전히 범위 밖이다(위 4번). 별도 이슈로 둔다.

## 7. 클릭 영역 — 토글과 상세 이동을 분리했다

- **디자인**: L109(체크 네모) · L111(항목명)은 같은 핸들러(`onToggleConsent`), L115(화살표)만 `onOpenConsentDetail` 이다.
- **구현**: 체크 네모와 항목명을 `<button role="checkbox">` **하나**로 묶고(버튼 안에 버튼을 넣지 않는다),
  화살표는 형제 `<Link>` 로 뒀다. 두 영역은 겹치지 않는다 — 실측으로 확인했다(토글 오른쪽 끝 309px = 화살표 왼쪽 끝 309px).
- **터치 영역**(`docs/07-screens.md:15` 최소 48×48): 두 조각 모두 보이는 크기는 디자인 그대로 두고,
  **음수 margin 으로 레이아웃 높이를 되돌리면서 클릭 상자만 48×48 로** 키웠다.
  토글은 `py-[11px]` + `-my-[11px]`(26 → 48), 화살표는 `size-12` + `-my-2 -mr-2`(32 → 48).
  덕분에 카드 높이(68px)와 화살표 중심(오른쪽에서 36px)이 디자인과 같은 값으로 남는다.
  `BackButton` 의 `after:-inset-*` 방식은 투명 영역이 옆 토글 위로 번져 쓰지 않았다.
- **문서 변경**: 불필요.

## 8. 디자인 원본 파일의 렌더 아티팩트 2가지 — 따라가지 않았다

`탄천런.dc.html` 을 브라우저로 열어 구현과 **실측 비교**(390×844 뷰포트)한 결과, 디자인 파일이 브라우저에서
그려지는 모습과 디자인의 의도가 어긋나는 지점이 두 군데 있었다. 둘 다 **의도를 따랐다.**

| 아티팩트 | 디자인 파일이 실제로 그리는 것 | 구현 | 왜 |
| --- | --- | --- | --- |
| 버튼 안 글자 | `[필수] 개인정보 수집·이용 동의` · `개인정보처리방침 보기` 가 **Arial** 로 나온다 | Pretendard | 디자인 마크업이 그 `<button>` 에만 `font-family` 를 빠뜨렸다(L111 · L122). 한글을 Arial 로 그리는 건 의도가 아니다 |
| 아이콘 굵기 | 모든 SVG 가 **stroke-width 1px** 로 나온다 | 2.4 · 3.2 | 원본이 React 식 `strokeWidth` 를 쓰는데 브라우저가 무시한다. 값은 소스에 그대로 적혀 있고, 이미 머지된 `BackButton`(2.4)도 같은 값을 쓴다 |

- **문서 변경**: 불필요. 디자인 파일을 눈으로 볼 때 이 두 가지는 실제 앱과 다르게 보인다는 점만 팀이 알면 된다.

## 9. 화면 아래 여백 22px — 디자인 목업의 노치는 빼고 맞췄다

- **디자인**: 콘텐츠 영역이 `padding:22px 20px`(L101) 라 계속하기 버튼 **아래로도 22px** 이 남고,
  버튼 블록 자체의 아래 여백 10px(L129)과 합쳐 화면 바닥까지 32px 이다.
- **구현**: 처음에 위쪽 22px 만 넣어 버튼이 22px 아래로 내려갔다. 실측으로 잡아 아래 22px 을 채웠다(바닥까지 32px 로 일치).
- **남는 차이**: 디자인 목업은 프레임 안에 **상태바(시각 31px)** 를 그려서 콘텐츠 높이가 813px 이고, 실제 앱은 844px 이다.
  그래서 목업에서는 버튼 위 빈 공간이 31px 더 좁다. 이건 기기의 노치 영역이라 따라가지 않는다 —
  실제 기기에서는 `AppShell` 의 safe-area 처리가 담당한다.
- **문서 변경**: 불필요.
