## 1. 닉네임 길이 — 문서 9자 이하, 디자인 2~10자

- **문서**: `docs/04-features.md:25` · `docs/05-policy.md:23` P10 — "닉네임은 필수이며 **9자를 넘을 수 없고**",
  안내 문구도 "닉네임은 9자 이하의 한글·영문·숫자만 쓸 수 있습니다". **하한이 없다.**
- **디자인 · 구현**: `2~10자`(L186 · L1194). `maxLength=10`, 유효 조건 `2 <= 길이 <= 10`.
  하한 2자가 새로 생겼고 상한이 9 → 10 으로 늘었다. 이슈 #39 「참고」가 디자인을 따르라고 지정했다.
- **고쳐야 할 곳**: `docs/04-features.md:25` 의 "9자 이하", `docs/05-policy.md:23` P10 의 길이 규칙과
  형식 위반 안내 문구. **닉네임 수정 화면(#51)도 같은 규칙을 쓰므로 함께 본다** — 디자인의 수정 화면
  검증(L1259)도 2~10자로 같다.

## 2. 재입력 안내가 문서는 3종, 디자인은 5종이다

- **문서**: `docs/05-policy.md:23` P10 — ① 미입력 "닉네임을 입력해 주세요" ② 형식 위반(9자 초과 ·
  공백 · 특수문자) "닉네임은 9자 이하의 한글·영문·숫자만 쓸 수 있습니다" ③ 중복 "이미 사용 중인 닉네임입니다".
  형식 위반 3가지를 **한 문구로 묶는다.**
- **디자인 · 구현**: 디자인(L1196-1202)은 형식 위반을 **공백 / 특수문자 / 2자 미만으로 쪼개** 각각 다른
  문구를 쓴다. 구현도 그대로 따랐다.

  | 사유 | 문구 | 출처 |
  | --- | --- | --- |
  | 미입력 | 닉네임을 입력해 주세요 | **문서 P10** (디자인에 없음) |
  | 공백 | 공백은 포함할 수 없습니다. | 디자인 L1198 |
  | 특수문자 | 특수문자는 사용할 수 없습니다. | 디자인 L1199 |
  | 중복 | 이미 사용 중인 닉네임입니다. | 디자인 L1200 (문서와 같은 문구) |
  | 2자 미만 | 2자 이상 입력해주세요. | 디자인 L1201 |
  | 유효 | 사용할 수 있는 닉네임입니다. | 디자인 L1202 |

  **미입력만 디자인에 문구가 없다.** 디자인은 빈 값일 때 아무 문구도 띄우지 않는데(`hasSignupMsg` false),
  이슈 AC 6번이 사유 3종을 요구하므로 문서 문구를 가져다 썼다 — 이슈 「참고」가 지정한 방식이다.
  **처음 진입했을 때는 띄우지 않고**, 입력했다가 지운 경우에만 띄운다(입력값 `null` = 아직 입력 안 함).
- **고쳐야 할 곳**: `docs/05-policy.md:23` P10 의 실패 사유 ②. 한 문구로 묶지 말고 공백 · 특수문자 ·
  길이 미만을 나눠 적는다. `docs/07-screens.md:46` 의 "미입력 · 9자 초과 · …" 열거도 같이 본다.

## 3. 뒤로 가기 버튼 — 이슈는 "없다", 디자인에는 있다

- **문서 · 이슈**: 이슈 #39 AC 7번 — "뒤로 가기 버튼이 **없다** — 이 화면에서 이탈할 수 없다".
  근거는 P11(`docs/05-policy.md:24`)과 `docs/07-screens.md:46` 의 "닉네임 설정을 마치기 전에 다른 화면으로
  가려 하거나 휴대폰 뒤로 가기를 누른다(**뒤로 가기는 무시한다**)".
- **디자인 · 구현**: 디자인 L171-173 에 `onBackToConsent` 뒤로가기 버튼이 **있다**. CLAUDE.md 10항이
  디자인을 기준으로 두므로 **버튼을 넣고** `backHref="/signup/consent"` 로 동의 화면에 붙였다.
  목적지가 가입 흐름 **안**이라 P11 이 막으려는 "다른 화면으로 넘어가기"에는 해당하지 않는다고 봤다.
- **고쳐야 할 곳**: `docs/07-screens.md:46` 의 "뒤로 가기는 무시한다" 한 줄. 무시 대상이 **앱 밖·본 화면으로
  나가는 이동**이고 가입 단계 사이 이동(동의 ↔ 닉네임)은 허용이라는 단서가 필요하다.
  **팀 판단이 필요한 항목이다** — 디자인이 맞다면 이슈 #39 AC 7번을 지워야 한다.

## 5. 저장 실패 상태는 만들지 않았다

- **디자인**: `nicknameSaveFails` 데모 prop 이 켜지면 "저장에 실패했습니다. 다시 시도해주세요."(L1197)를
  띄운다. 다른 안내보다 **우선순위가 가장 높다.**
- **구현**: 저장할 서버가 없다. 실패를 만들어 낼 실제 트리거가 없으므로 **가짜 실패를 넣지 않았다**
  (로그인 화면이 `/login?error=` 로 실패 안내를 띄우는 것과 같은 원칙). "시작하기" 를 눌러도 아직 아무
  일도 일어나지 않는다 — `saveNickname()` 에 `TODO(F10 · P10)` 만 있다.
- **고쳐야 할 곳**: 문서가 아니다. 인증·API 트랙이 붙을 때 이 화면에 저장 실패 분기를 추가한다.

## 6. 줄높이 차이가 여기서도 그대로 나온다 (앱 전역 · #39 원인 아님)

원인과 판단은 [2026-09-14-signup-consent-detail.md](2026-09-14-signup-consent-detail.md) 6번과 같다 —
Tailwind preflight 의 `html { line-height: 1.5 }` 가 디자인의 `normal` 보다 크다. **이 화면에서 잰 값만 남긴다.**

디자인 프레임은 상단에 상태바(31px)가 있고 구현에는 없어서, 아래 「디자인」 열은 상태바를 뺀 값이다.

| 항목 | 디자인 | 구현 | 차이 |
| --- | --- | --- | --- |
| 헤더 높이 | 59px | 59px | 0 |
| 수달 이미지 높이 | 216px | 216px | 0 |
| `닉네임 설정` 제목 높이 | 38px | 48px | **+10** (32px × 1.5) |
| 입력 카드 높이 | 65px | 70px | **+5** (21px × 1.5) |
| 안내 문구 높이 | 16px | 20px | +4 |
| 안내 문구 y | 589px | 612px | **+23** (누적) |
| 시작하기 버튼 | `x=28 334×60` | `x=28 334×60` | 0 |
| 버튼 아래 여백 | 34px | 34px | 0 |

카드 `x=28 w=334`, 이미지 높이, 버튼 크기·위치·아래 여백은 정확히 일치한다. 버튼이 `mt-auto` 로 바닥에
붙어 있어 위쪽의 누적 차이가 버튼 위치로 새지 않는다.

**고쳐야 할 곳**: 문서가 아니라 팀 결정 사항이다. #38 에 적은 제안(`globals.css` 에 기준 줄높이를 둔다)이
그대로 유효하고, 화면이 늘수록 같은 기록이 반복된다.
