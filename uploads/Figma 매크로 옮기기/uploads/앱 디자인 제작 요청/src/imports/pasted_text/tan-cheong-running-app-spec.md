첨부한 01-problem.md, 02-workflow.md, 03-requirements.md, 04-features.md, 05-policy.md, 06-backlog.md를 분석하여
**탄천 로컬 개인 랭킹전 모바일 앱의 와이어프레임, UI 디자인, 클릭 가능한 프로토타입**을 만들어줘.

# 1. 가장 중요한 원칙

- 01~05 문서를 현재 MVP의 기준으로 사용한다.
- 06-backlog.md는 제외·후순위 기능을 확인하기 위한 참고 문서로만 사용하고, 해당 기능은 현재 MVP에 구현하지 않는다.
- 문서에 없는 기능이나 정책을 임의로 추가하지 않는다.
- Workflow, Requirements, Features, Policy에 정의된 내용을 최대한 정확하게 UI와 인터랙션에 반영한다.
- 기능적으로 불명확한 부분을 임의로 확정하거나 새로운 정책을 만들지 않는다.
- 단순히 예쁜 러닝 앱을 만드는 것보다 **현재 기획안을 실제 사용 가능한 모바일 앱 화면으로 옮기는 것**을 우선한다.
- 기능 구조와 사용자 Workflow를 먼저 정확하게 구현한 뒤 Visual Design을 적용한다.

---

# 2. 서비스 정의

이 앱은 **성남 탄천 주변에서 달리는 뉴비 러너를 위한 로컬 개인 러닝 랭킹 서비스**다.

사용자는 어디에서 달리든 자신의 전체 러닝 기록을 저장할 수 있다.

하지만 랭킹에는 전체 러닝 거리가 아니라
**탄천 Ranking Zone 내부에서 실제로 달린 거리만 누적된다.**

따라서 서비스의 핵심은 다음 3가지다.

1. 개인 러닝 기록
2. GPS 기반 탄천 Ranking Zone 거리 판정
3. 탄천 인정 누적 거리 기반 개인 랭킹

크루나 팀 경쟁이 아니라 **개인 단위의 로컬 경쟁**이다.

# 3. 핵심 사용자 Workflow

다음 흐름이 실제 프로토타입에서 자연스럽게 이어지도록 설계한다.

소셜 로그인
→ 닉네임 설정
→ 러닝 시작 화면
→ GPS 상태 확인
→ GPS 정상 확인 후 러닝 시작 버튼 활성화
→ 러닝 시작 버튼 클릭
→ 3초 카운트다운
→ 러닝 진행
→ 사용자가 직접 러닝 종료
→ 러닝 결과
→ 랭킹 확인 또는 개인 기록 확인

---

# 4. 핵심 화면

## 4-1. 소셜 로그인

- 카카오 로그인
- 구글 로그인
- 인증 성공 → 닉네임 설정 화면 이동
- 인증 실패 또는 취소 → 로그인 실패 상태 안내

복잡한 회원가입 폼을 새로 만들지 않는다.

---

## 4-2. 닉네임 설정

- 사용자가 닉네임을 직접 입력한다.
- 닉네임은 필수 입력이다.
- 다른 사용자와 중복된 닉네임은 사용할 수 없다.
- 미입력 상태에서는 다음 단계로 진행할 수 없다.
- 중복된 닉네임이면 재입력을 안내한다.
- 정상 설정 후 앱의 메인 흐름으로 이동한다.

---

## 4-3. 홈 / 러닝 시작

앱의 핵심 진입 화면이다.

사용자를 친근하게 맞이하고 러닝 시작 기능에 가장 쉽게 접근할 수 있도록 한다.

예:
“안녕하세요, ○○님 👋”

현재 자신의 탄천 랭킹 정보를 확인할 수 있게 하되,
랭킹이 홈 전체를 지배하는 공격적인 경쟁 UI가 되지 않도록 한다.

**러닝 시작을 핵심 CTA로 명확하게 표현한다.**

화면 진입 시 백그라운드에서 GPS 상태를 먼저 확인한다.

### GPS 확인 전 또는 사용 불가

- 러닝 시작 버튼 비활성화
- “GPS 신호를 확인할 수 없어 러닝을 시작할 수 없습니다” 안내

### GPS 확인 완료

- 러닝 시작 버튼 활성화

사용자가 활성화된 버튼을 누르면 GPS를 다시 확인하는 절차를 만들지 않는다.

바로 3초 카운트다운으로 이동한다.

---

## 4-4. 3초 카운트다운

화면 중앙에

3 → 2 → 1

을 크게 표시한다.

카운트다운은 GPS 확인 과정이 아니라 사용자가 러닝을 준비하기 위한 신호다.

카운트다운 종료 후 러닝 진행 화면으로 자동 전환한다.

---

## 4-5. 러닝 진행

야외에서 달리는 중 빠르게 정보를 확인할 수 있도록 다른 화면보다 정보 가독성을 더욱 중요하게 설계한다.

다음 4개 정보를 실시간으로 표시한다.

- 총 러닝 거리
- 탄천 인정 누적 거리
- 러닝 시간
- 현재 페이스

숫자를 크고 명확하게 보여준다.

**러닝 종료 버튼은 항상 화면에서 확인할 수 있어야 한다.**

### 중요한 제한

러닝 진행 중에는
- 현재 순위
- 랭킹

을 보여주지 않는다.

순위는 러닝 완료 후에만 확인한다.

### GPS 신호 이상

GPS 신호가 2초 이상 끊기면

- GPS 경고 아이콘
- “GPS 신호가 약합니다”

를 표시한다.

GPS가 끊긴 동안에는 거리와 탄천 인정 거리가 증가하지 않는다.

GPS가 복구되면 복구된 지점부터 다시 측정한다.

---

## 4-6. 러닝 결과

사용자가 직접 러닝 종료 버튼을 누르면 결과 화면으로 이동한다.

다음 정보를 명확하게 보여준다.

1. 총 러닝 거리
2. 탄천 Ranking Zone 인정 거리
3. 누적 거리 기준 개인 순위
4. 러닝 시간
5. 페이스
6. 일자

탄천 인정 거리가 0인 러닝은 순위 영역에

**“랭킹 미반영”**

이라고 표시한다.

이번 러닝으로 개인 최고 기록(PR)이 갱신되었다면 결과 화면에서 자연스럽게 알려준다.

PR을 지나치게 게임적인 연출이나 화려한 효과로 표현하지 않는다.

---

## 4-7. 랭킹

탄천 Ranking Zone 내부에서 측정된
**누적 거리 기준 전체 개인 랭킹**을 보여준다.

각 사용자에게 표시할 정보는 다음으로 제한한다.

- 순위
- 닉네임
- 누적 탄천 인정 거리

다른 사용자의 프로필이나 상세정보로 이동하는 기능은 만들지 않는다.

사용자 자신의 순위는 부드러운 Background Highlight 정도로 구분한다.

랭킹 데이터가 없는 경우 Empty State를 보여준다.

랭킹을 스포츠 경기 순위표처럼 딱딱하거나 공격적으로 표현하지 말고
**“우리 동네 러너들의 기록을 함께 보는 느낌”**으로 디자인한다.

1~3위를 지나치게 화려한 금·은·동 메달, 왕관, 게임 효과 등으로 강조하지 않는다.

---

## 4-8. 기록

사용자의 과거 러닝 기록을 일자별 목록으로 보여준다.

각 기록에는

- 일자
- 총 러닝 거리
- 탄천 인정 거리
- 러닝 시간
- 평균 페이스

를 표시한다.

같은 기록 영역에서 개인 최고 기록도 확인할 수 있도록 한다.

### 개인 최고 기록

- 최장 거리
- 최고 페이스
- 최대 운동 시간

첫 러닝이라면 해당 기록 자체가 최초 개인 최고 기록이 된다.

기록이 하나도 없는 신규 사용자는

**“아직 기록이 없습니다”**

Empty State를 보여준다.

---

# 5. Navigation

모바일 앱에 적합한 Bottom Navigation을 사용한다.

핵심 영역은

**러닝 / 랭킹 / 기록**

을 중심으로 구성한다.

러닝 시작은 사용자가 가장 쉽게 접근할 수 있는 핵심 CTA로 표현한다.

기획안에 없는 메뉴를 Bottom Navigation에 임의로 추가하지 않는다.

---

# 6. Visual Design Concept

전체 디자인의 핵심 컨셉은

**“동네에서 부담 없이 함께 달리는 따뜻한 로컬 러닝 앱”**

이다.

이 서비스는 전문 선수나 하드코어 러너를 위한 앱이 아니다.

탄천 주변에서 러닝을 시작하거나 꾸준히 달리고 싶은 뉴비 러너들이
자신의 기록을 관리하면서 주변 러너들과 가볍게 경쟁해 동기부여를 얻는 서비스다.

따라서

**심플함 + 따뜻함 + 친근함 + 러닝 기록 앱의 전문성**

이 동시에 느껴지도록 디자인한다.

사용자가 처음 앱을 봤을 때

“운동 잘하는 사람들만 사용하는 전문 러닝 앱”

보다는

**“우리 동네에서 부담 없이 뛰면서 기록도 쌓고 주변 러너들과 가볍게 경쟁하는 앱”**

이라는 인상을 받아야 한다.

첨부한 레퍼런스 이미지의 밝고 부드러운 전체 분위기를 참고하되,
화면을 그대로 복제하지 말고 이 서비스의 기능 구조에 맞게 재해석한다.

---

# 7. 피해야 할 Visual Style

Nike Run Club과 같은 강한 스포츠 앱 스타일을 사용하지 않는다.

특히 다음 스타일을 피한다.

- 검정색 중심의 Dark UI
- Black Background 중심 디자인
- Neon Green
- 형광색
- 지나치게 강렬한 대비
- Glow Effect
- 공격적인 스포츠 Typography
- 하드코어 운동 앱 분위기
- 지나치게 경쟁적인 랭킹 디자인
- 게임처럼 과장된 랭킹 효과

**기본 화면은 Dark Mode가 아닌 밝은 Light UI로 제작한다.**

---

# 8. Color Direction

전체 Background는 pure white만 반복하지 말고

- Warm Gray
- Off-white
- 아주 연한 Cream

등을 활용하여 따뜻하고 편안한 느낌을 만든다.

Primary Color는 첨부 레퍼런스처럼 **밝고 깨끗한 Blue 계열**을 사용한다.

단,
- Neon Blue
- 지나치게 차가운 Electric Blue

느낌은 피한다.

필요한 경우 Secondary / Accent Color로

- Soft Blue
- Warm Beige
- Soft Green
- Cream

등 자연스럽고 부드러운 색상을 제한적으로 사용할 수 있다.

색상을 너무 많이 사용하지 말고 전체 Palette를 일관되게 유지한다.

---

# 9. UI Style

## Card

- 밝은 배경
- 충분한 Border Radius
- 약한 Shadow 또는 Border
- 카드 사이 충분한 여백
- 지나치게 많은 카드를 한 화면에 배치하지 않는다.

## Button

- 크고 누르기 쉬운 Touch Target
- 둥근 모서리
- Primary Blue 중심
- 핵심 CTA가 명확하게 보이도록 한다.
- Gradient와 Glow Effect는 사용하지 않는다.

## Typography

- 러닝 거리·시간·페이스 등의 숫자는 크고 명확하게 표현한다.
- 일반 텍스트는 부드럽고 읽기 쉬운 Typography를 사용한다.
- 지나치게 굵고 공격적인 스포츠 Typography는 피한다.
- 정보의 중요도에 따라 명확한 계층을 만든다.

## Icon

- 단순하고 직관적
- 부드럽고 둥근 형태
- 지나치게 날카롭거나 기계적인 아이콘은 피한다.

---

# 10. 화면별 Visual Tone

## 홈

가장 친근하고 편안한 화면으로 만든다.

사용자 인사 → 현재 상태 → 러닝 시작 CTA가 자연스럽게 이어지게 한다.

현재 탄천 순위는 중요한 정보지만 홈 화면 전체에서 가장 공격적으로 강조하지 않는다.

**러닝 시작과 현재 러닝 상태가 우선이고, 랭킹은 동기부여 정보로 자연스럽게 제공한다.**

## 랭킹

“경쟁”보다는 **친근한 로컬 경쟁**의 느낌을 준다.

닉네임과 누적 거리를 중심으로 간결하게 보여준다.

## 기록

개인의 성장과 꾸준함을 확인하는 차분한 화면으로 만든다.

PR과 과거 기록을 쉽게 구분할 수 있게 하되 지나친 성취 효과는 사용하지 않는다.

## 러닝 진행

다른 화면보다 정보 집중도를 높인다.

총 거리 / 탄천 인정 거리 / 시간 / 페이스를 빠르게 읽을 수 있도록 큰 숫자와 높은 가독성을 사용한다.

러닝 중에도 Black + Neon 디자인으로 바꾸지 않고 전체 Light Visual System과 일관성을 유지한다.

---

# 11. MVP에서 절대 추가하지 않을 기능

06-backlog.md의 후순위·제외 기능은 현재 화면에 구현하지 않는다.

특히 다음 기능을 임의로 추가하지 않는다.

- 크루 / 팀
- 친구 / 팔로우
- 피드
- 댓글
- 채팅
- 다른 사용자 프로필
- 전국 랭킹
- 티어 / 레벨
- 주간·월간 랭킹
- TOP100 제한
- 목표 거리 설정
- 목표 시간 설정
- 다음 순위까지 남은 거리
- 러닝 일시정지
- 자동 종료
- 러닝 경로 지도
- 기록 정렬 / 필터
- 스마트워치 연동
- 음성 안내

현재 MVP는

**개인 러닝 기록 + GPS 기반 탄천 Ranking Zone 판정 + 탄천 누적 거리 개인 랭킹**

에 집중한다.

---

# 12. 프로토타입 요구사항

정적인 UI Mockup만 만들지 말고 주요 버튼과 화면을 실제로 연결하여
**클릭 가능한 모바일 앱 프로토타입**으로 제작한다.

다음 Main Flow는 반드시 테스트할 수 있어야 한다.

로그인
→ 닉네임 설정
→ GPS 확인
→ 러닝 시작
→ 3초 카운트다운
→ 러닝 진행
→ 종료
→ 러닝 결과
→ 랭킹

Bottom Navigation을 통해

**러닝 / 랭킹 / 기록**

사이를 이동할 수 있게 한다.

GPS 오류, 기록 없음, 랭킹 미반영 등 기획안에 명시된 주요 상태도 UI에서 확인할 수 있게 한다.
