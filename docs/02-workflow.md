## 흐름
S1 → S2 → S3 · 분기: (1) 탄천 구역 내/외 러닝에 따라 랭킹 반영 여부가 갈린다(구역 내는 개인 기록 + 랭킹 반영, 구역 외는 개인 기록만) (2) GPS 신호가 끊긴 구간은 끊기기 전후 이동 패턴을 바탕으로 구간을 예상하여 처리한다

## 발산 질문 — 아직 말하지 않은 단계 · 불편 · 이해관계자

> 아래는 팀이 채택 · 거절을 정하는 후보다. 01문서에서 이미 [확정] · [보류] · [확장-게임요소] · [폐기]로 정리된 내용과 겹치지 않는 새 후보 위주로 냈다.

### 1) 이 행위자가 겪을 수 있는데 아직 말하지 않은 단계 · 불편

- [확정] S1: 위젯을 눌렀지만 아직 속도 감지가 안 되어 측정이 실제로 시작되지 않았는데도 러너는 "이미 기록 중"이라고 착각해 초반 구간이 누락될 수 있다 (근거: S1 To-Be "일정 속도 감지되면 진동 등으로 알림" — 버튼을 누른 시점과 실제 측정 시작 시점 사이에 시차가 있음) → 팀 결정: 측정 시작 버튼 후 카운트 다운 보여주고 달릴 수 있게 함. (소리 On/Off)
- [폐기] S2: 장시간 러닝 시 GPS · 화면 사용으로 배터리 소모가 커서 중간에 폰이 꺼지거나 앱이 백그라운드에서 종료되어 추적이 끊길 수 있다 (근거: S2 행동 "달린다" — 장시간 백그라운드 GPS 추적에 따른 자원 소모는 아직 다뤄지지 않음) → 팀 결정: 배터리 자원 소모는 현재 우리의 영역이 아님
- [보류] S3: 신호 대기 · 벤치 휴식 등으로 잠시 멈췄을 때 "정지 후 2분" 자동 종료 규칙 때문에 의도치 않게 러닝이 끝나버릴 수 있다 (근거: S3 To-Be "속도 줄어들기 또는 정지 후 2분 지나면 자동 종료" — 일시 정지와 완전 종료를 구분하는 규칙이 아직 없음) → 팀 결정: 5분으로 시간을 늘리거나, 종료할거냐고 진동 알림 등을 해서 인지하게 해야할 듯. 다이빙의 경우 다이브컴퓨터가 기압을 인지하기 때문에 알아서 시작 종료를 해주지만, 해당 서비스는 조절할 수 있는 부분이 크게 없음.
- [폐기] S3: 결과 · 랭킹을 확인했을 때 "불만족"을 느껴도 그 이유(탄천 구역 밖 거리 비중, 신호 오차 구간 등)를 확인할 방법이 없어 답답할 수 있다 (근거: S3 감정 "본인 기록에 만족하거나 불만족" — 불만족의 원인을 스스로 확인할 경로는 언급되지 않음) → 팀 결정: 해당 영역의 불만족은 우리가 컨트롤할 수 있는 영역이 아님. 개인의 만족감.

### 2) 이 일에 얽힌, 문서에 등장하지 않는 다른 사람

- [보류] 랭킹 · 기록 오류(예: GPS 오차로 억울한 판정) 문의를 접수하는 고객 문의 대응 담당자 — S3에서 나온 "불만족" 상황을 실제로 해소해줄 창구가 필요할 수 있다 (근거: S3 감정 "불만족" 및 01문서 발산 질문에서 [확정]된 GPS 오차 문제) → 팀 결정: 운영자에 속하는 부분은 나중에 다루도록 할테니 보류
- [폐기] 위젯 · 백그라운드 위치 권한 등 OS 정책을 관리하는 스마트폰 플랫폼(안드로이드/iOS) 쪽 제약 — 팀이 만들 위젯 원터치 시작, 속도 기반 자동 시작 · 종료 기능이 OS 정책에 막힐 수 있다 (근거: S1 · S3 To-Be에서 "위젯", "자동 종료" 등 OS 백그라운드 동작을 전제로 함) → 팀 결정: OS 정책 쪽도 아직 우리의 영역이 아니기 때문에 폐기
