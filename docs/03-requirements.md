## 요구사항

| R | 행위자(A) | 요구 (\~할 수 있어야 한다) | 출처(S · 인터뷰 · [제안] 근거) | 유형 | 중요도 |
| - | -------- | ---------------------- | ---------------------------- | ---- | ------ |
| R1 | A1 | GPS 사용이 불가능한 경우 러닝을 시작하지 않고 오류 안내를 받을 수 있어야 한다 | S1 | 기능 | 중 |
| R2 | A1 | 러닝 중 현재 총 러닝 거리를 확인할 수 있어야 한다 | S2 | 기능 | 중 |
| R3 | A1 | 러닝 중 현재 러닝 시간을 확인할 수 있어야 한다 | S2 | 기능 | 중 |
| R4 | A1 | 러닝 중 현재 탄천 인정 누적 거리를 확인할 수 있어야 한다 | S2 | 기능 | 중 |
| R5 | A1 | 러닝 중 GPS 신호가 2초 이상 끊기면 경고를 확인할 수 있어야 한다 | S2 | 기능 | 중 |
| R6 | A1 | 러닝 중 GPS로 총 러닝 거리, 탄천 인정 거리, 페이스, 달린 시간이 실시간으로 지속 갱신되어야 하며, 순위는 러닝 중에는 보여줄 필요가 없다(완료 후 결과 화면·랭킹 화면에서만 확인 가능). 러닝 종료 버튼은 별도로 보여야 한다. GPS 신호가 끊긴 구간은 거리 계산에서 제외하고, 신호가 복구되면 그 지점부터 다시 측정할 수 있어야 한다 | S2 | 제약 | 상 |
| R7 | A1 | 탄천 Ranking Zone 누적 거리 기준 순위를 확인할 수 있어야 한다 | S5 | 기능 | 상 |
| R8 | A1 | Ranking Zone 안팎과 관계없이 개인 러닝 기록(총 러닝 거리·탄천 인정 거리·시간·평균페이스)가 일자별로 계속 저장하고 확인될 수 있어야 하며, R10에서 언급하는 최고 기록은 별도로 기록되며 저장되어야 한다. 예를 들어서 영역 밖에서만 뛴 러너는 탄천 인정 거리가 0이어야 한다.| S6 | 기능 | 상 |
| R9 | A1 | 과거 러닝 기록을 목록으로 조회할 수 있어야 한다 | 01 유사 서비스 절(NRC·Strava 핵심 기능인 러닝 히스토리 리스트) + S6 | 기능 | 중 |
| R10 | A1 | 자신의 개인 최고 기록(최장 거리·최고 페이스·최대 운동 시간 등)을 확인할 수 있어야 한다 | S6 불편(자신의 성장을 확인하고 싶은 사용자) + 01 유사 서비스 절 | 기능 | 중 |
| R11 | A1 | 탄천 Ranking Zone 내부에서 측정된 거리만 랭킹에 반영되어야 한다 | 01 핵심 차별점(구역 판정 룰) + S4·S5 | 제약 | 상 |
| R12 | A1 | 탄천 Ranking Zone 외부에서 측정된 거리도 개인 러닝 기록에는 포함되어야 한다 | 01 핵심 차별점(구역 판정 룰) + S4·S6 (R8과 연결되는 반영 규칙을 명시적으로 분리) | 제약 | 상 |
| R13 | A1 | 카카오·구글 등 소셜 로그인으로 간편하게 가입·로그인할 수 있어야 한다 | S0 | 기능 | 상 |
| R14 | A1 | 러닝 종료 후 결과 화면에서 총 러닝 거리, 탄천 Ranking Zone 인정 거리, 개인 순위(누적 거리 기준), 러닝 시간, 페이스(속력), 일자를 확인할 수 있어야 한다 | S4 | 기능 | 상 |
| R15 | A1 | 가입 시 닉네임을 직접 설정해야 한다(필수 입력). 닉네임은 다른 사용자와 중복될 수 없다 | S0 (R13과 연결된 가입 절차) | 데이터 | 중 |
| R16 | A1 | 러닝 시작 버튼을 클릭하면 3초 카운트다운 후 러닝이 시작되는 것을 확인할 수 있어야 한다 | S1 | 기능 | 중 |
| R17 | A1 | 러닝 중 현재 페이스(속력)를 확인할 수 있어야 한다 | S2 | 기능 | 중 |

> 주: R6은 "순위는 러닝 중에는 보여줄 필요가 없다"는 내용을 각주가 아닌 본문에 직접 명시했다(팀 요청).
> 주: R11·R12는 반영 조건(어떤 거리가 랭킹/개인기록에 포함되는지)을 명시적으로 분리한 제약 요구사항이라, R7·R8은 "확인할 수 있다"는 화면 기능만 남아 유형을 "기능" 하나로 단순화했다.
