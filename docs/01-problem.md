## 4요소

| 칸        | 내용                                                                                                                                                                                                  |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **문제**   | 러닝 크루에 속한 사용자가 GPS 앱으로 개인 러닝 기록을 남겨도 **자신의 러닝이 크루 전체의 성과나 다른 크루와의 경쟁으로 연결되는 경험이 부족하다.**                                                                                                             |
| **대상**   | 성남 **탄천을 중심으로 러닝하는 개인 러너 및 러닝 크루 구성원**                                                                                                                                                              |

| **불편**   | 개인이 얼마나 달렸는지는 확인할 수 있지만 **“내가 오늘 달린 거리가 우리 크루에 얼마나 기여했고, 그 결과 다른 크루와의 순위가 어떻게 변했는지”를 즉각적으로 체감하기 어렵다.** 크루 단위 기록을 따로 관리하려면 구성원의 기록을 다시 확인하고 합산해야 한다. 실제로 크루들이 이런 불편을 얼마나 크게 느끼는지는 인터뷰를 통해 확인할 필요가 있다 |

## 한 문단으로

탄천에서 러닝하는 개인 러너와 러닝 크루 구성원은 기존 러닝 앱을 이용해 거리, 시간, 평균 페이스와 같은 개인 기록을 확인할 수 있지만, 자신의 러닝 기록이 크루 전체의 성과와 다른 크루와의 경쟁 결과로 직접 연결되는 경험은 부족하다. 따라서 사용자가 GPS로 러닝한 기록을 기본적인 **개인 러닝 기록으로 저장**하면서, 그중 탄천과 같은 지정 Ranking Zone에서 달린 거리만 크루 점수에 반영하여 **“내 러닝 → 크루 기여 → 랭킹 변화”**를 바로 확인할 수 있도록 한다.

## 확인할 수 없어 표시해 둔 것

* **“러닝 크루 구성원들이 다른 크루와 경쟁하고 싶어 한다”** — 현재 팀의 가설이다. 실제 러닝 크루 사용자에게 물어봐야 한다.
* **“기존 러닝 앱에서는 크루 간 경쟁에 대한 만족도가 낮다”** — 현재 가설이다. 기존 서비스 사용 경험과 함께 인터뷰에서 확인한다.
* **“탄천을 하나의 Ranking Zone으로 설정하면 경쟁에 참여하고 싶어질 것이다”** — 서비스의 핵심 가설이다. 사용자 인터뷰 및 MVP 테스트가 필요하다.
* **“크루 랭킹이 러닝 동기를 높인다”** — 핵심 가치 가설이므로 실제 사용자를 대상으로 확인해야 한다.
* **“성남 · 탄천 러너들이 크루 단위로 기록을 따로 합산하거나 관리하고 있다”** — 실제 사용 행태를 조사해야 한다.
* Strava · Nike Run Club · adidas Running의 구체적인 최신 기능과 크루 경쟁 지원 범위는 **팀원이 직접 서비스를 사용하거나 공식 자료를 통해 확인한 뒤 작성한다.**

## MVP에서 해결할 범위

이번 MVP에서는 모든 러닝 문제를 해결하지 않는다.

해결하려는 핵심 범위는 다음과 같다.

### 1. 개인 러닝 기록

사용자는 어디에서 달리더라도 자신의 러닝 기록을 저장할 수 있다.

최소 기록:

* 러닝 거리
* 러닝 시간
* 평균 페이스
* GPS 이동 경로
* 러닝 날짜

즉,

> **“내가 언제, 어디서, 얼마나 달렸는가?”**

를 확인할 수 있어야 한다.

### 2. 탄천 Ranking Zone 판정

GPS 러닝 기록 중 운영자가 지정한 **탄천 Ranking Zone 안에서 발생한 이동 거리**를 별도로 계산한다.

예:

전체 러닝 거리: **10km**

탄천 인정 거리: **7km**

개인 러닝 기록: **10km**

크루 기여 거리: **7km**

### 3. 크루 기록

사용자가 크루에 속해 있다면 탄천 인정 거리를 해당 크루의 주간 기록에 누적한다.

### 4. 크루 랭킹

각 크루의 주간 탄천 인정 거리를 합산하여 순위를 보여준다.

예:

1위 RunKing — 142.5km
2위 Pace Makers — 138.2km
3위 Night Runner — 121.7km

사용자는 자신의 러닝 종료 후

> **“내가 5km를 달렸고 그중 4.7km가 크루 점수에 반영되어 우리 크루가 2위에서 1위가 되었다.”**

와 같은 결과를 확인할 수 있어야 한다.

## 이번 MVP에서 해결하지 않는 문제

다음 기능도 러닝 동기부여에 의미가 있지만, 현재 핵심 문제를 검증하기 위해 반드시 필요한 기능은 아니므로 후순위로 둔다.

* 개인 목표 설정
* 개인 티어 시스템
* XP / Level
* Badge · Achievement
* Streak
* 개인 챌린지
* Mock Payment
* 실패 페널티
* Duolingo 스타일 Push Notification
* 라이벌 크루 지정
* 크루 채팅
* 게시판 · 피드
* 친구 기능
* 여러 지역 Ranking Zone
* 러닝 경로 Replay Animation
* 실시간 다른 사용자 위치 공유
* 고급 GPS 치팅 탐지

향후에는 개인 러닝 기록을 기반으로

**러닝 → 개인 목표 달성 → XP → Tier 상승**

이라는 **개인 성장 Loop**를 추가할 수 있다.

하지만 MVP에서는 먼저

**러닝 → 탄천 인정 거리 → 크루 기여 → 크루 랭킹 변화**

라는 **크루 경쟁 Loop**가 실제로 사용자에게 동기부여가 되는지를 검증한다.

## MVP 핵심 문제 정의

> **탄천에서 달리는 러너가 자신의 GPS 러닝 기록을 개인 기록으로 관리하면서, 탄천에서 달린 거리가 자신이 속한 크루의 점수에 즉시 반영되고 다른 크루와의 주간 순위 변화로 이어지는 경험을 제공한다.**

MVP가 검증해야 할 핵심 질문은 다음과 같다.

> **“내가 달린 거리가 우리 크루의 순위를 바꾼다는 경험이 사용자를 다시 달리게 만드는가?”**
