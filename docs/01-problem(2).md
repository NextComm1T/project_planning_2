## 4요소

| 칸        | 내용                                                                                                                              |
| -------- | ------------------------------------------------------------------------------------------------------------------------------- |
| **문제**   | 기존 앱의 전국 · 글로벌 단위 랭킹은 너무 방대해 **내 순위가 무의미하며**, 혼자만의 숫자 경신은 금방 지루해진다.                                                             |
| **대상**   | 성남 **탄천 주변에 거주하며 달리기를 즐기거나 습관을 만들고 싶은 개인 러너**                                                                                   |
| **현재해법** | NRC, Strava 등으로 개인 기록을 측정한다.                                                                                                    |
| **불편**   | 매일 달리는 **우리 동네인 탄천**이라는 친숙한 공간에서, 나와 비슷한 코스를 뛰는 이웃들과 가볍고 재미있게 경쟁하며 동기부여를 얻을 창구가 없다. 또한 기존 방식으로는 동네에서의 내 위치나 성과를 가시적으로 확인하기 어렵다. |

## 한 문단으로

성남 탄천 주변에 거주하며 달리기를 즐기거나 습관을 만들고 싶은 개인 러너는 NRC, Strava 등을 통해 개인 러닝 기록을 측정하고 있지만, 전국 · 글로벌 단위의 랭킹은 너무 방대해 자신의 순위가 무의미하게 느껴지고 혼자만의 숫자 경신 역시 금방 지루해질 수 있다. 매일 달리는 **탄천이라는 친숙한 공간에서 나와 비슷한 코스를 뛰는 이웃들과 개인 단위로 가볍고 재미있게 경쟁하며 동기부여를 얻을 수 있는 창구가 필요하다.**

## 핵심 차별점 — 구역 판정 룰

크루 간의 복잡한 밸런스 붕괴 문제를 없애고, 오직 **장소(Ranking Zone)**와 **개인**에만 집중한다.

| 러닝 위치          | 개인 기록 저장 | 탄천 지역 랭킹 거리 합산 |
| -------------- | -------- | -------------- |
| **탄천 구역 내 러닝** | O        | O              |
| **탄천 구역 외 러닝** | O        | X              |

유저는 어디서든 자유롭게 앱을 사용할 수 있지만, **랭킹을 올리기 위해서는 탄천에서 달려야 한다.**

이를 통해 탄천으로 나가 달리게 만드는 명확한 동기부여와 게임 요소를 제공한다.

## MVP 핵심 워크플로우

### 1. 러닝 기록

유저가 앱을 켜고 자유롭게 달린다.

### 2. GPS 구역 판정

러닝 종료 시 시스템이 유저의 GPS 이동 경로를 분석하여 **탄천 지정 구역(Ranking Zone)** 내에서 이동한 거리만 필터링한다.

### 3. 결과 분리 및 랭킹 반영

오늘 달린 총 거리(예: **7km**)는 개인 러닝 기록 페이지에 저장된다.

그중 탄천 구역에서 달린 거리(예: **4.5km**)는 이번 주 탄천 랭킹 점수에 즉시 누적된다.

이후 유저에게 자신의 **순위 상승 결과**를 화면에 보여준다.

## MVP 개발 제약 사항

* **크루(팀) 관련 모든 기능 금지**

  * 팀 단위 합산 제외
  * 길드 가입 등 크루 시스템 전면 폐지
  * 철저히 **개인 단위 랭킹만 존재**

* **불필요한 소셜 기능 금지**

  * 친구 추가 제외
  * 다른 유저의 프로필 보기 제외
  * 피드 제외
  * 댓글 제외
  * 채팅 제외

* **전국 단위 랭킹 금지**

  * 랭킹보드는 오직 **탄천 구역 데이터만 취급**

## 프로젝트 한 줄 정의

> **개인의 전체 러닝 기록은 관리하되, 오직 지정된 구역인 탄천에서 달린 거리만 합산하여 로컬 주민들끼리 개인 랭킹 경쟁을 펼치는 동기부여 서비스**

## 발산 질문 — 아직 말하지 않은 단계 · 불편 · 이해관계자

> 아래는 팀이 채택 · 거절을 정하는 후보다. 확정된 것이 아니며, 다음 인터뷰(특히 02 업무 분석)에서 팀이 답하면 그 답이 우선한다.

### 1) 이 행위자가 겪을 수 있는데 아직 말하지 않은 단계 · 불편

- [확정] 러닝 시작 전 GPS/위치 권한을 켜고 신호를 잡는 준비 시간이 필요할 수 있다 (근거: MVP 핵심 워크플로우 "1. 러닝 기록" — "유저가 앱을 켜고 자유롭게 달린다"는 바로 달리는 것으로만 적혀 있고 준비 단계가 없음) → 팀 결정: 러닝 측정 버튼을 눌러야 하며, 백그라운드에서 GPS 기반으로 특정 속도가 감지되면 측정을 시작하는 예비 측정 방식으로 진행한다.
- [확정] 탄천 구간 중 다리 밑 · 건물 밀집 구간에서 GPS 신호가 불안정해 구역 판정이 실제와 다르게 나올 수 있고, 이때 유저가 억울함을 느낄 수 있다 (근거: "2. GPS 구역 판정" — GPS 이동 경로 분석으로 거리를 필터링한다고만 되어 있고 오차 · 예외 상황 언급 없음) → 팀 결정: 신호가 끊긴 구간은 끊기기 전후 이동 패턴을 바탕으로 구간을 예상하여 측정한다.
- [보류] 러닝을 잘못 시작했거나 중간에 앱이 꺼졌을 때 기록을 취소 · 재측정하지 못해 억울해할 수 있다 (근거: "3. 결과 분리 및 랭킹 반영" — 저장 · 반영만 있고 취소 · 정정 경로 없음) → 팀 결정: 보류.
- [확정] 결과 화면(순위 상승 결과)을 보기까지 GPS 분석 · 서버 처리 대기 시간이 생기고, 이 대기가 길면 성취감이 식을 수 있다 (근거: "3. 결과 분리 및 랭킹 반영" 마지막 줄) → 팀 결정: 3초 내에 결과를 볼 수 있게 설계하거나, 처리 시간이 지루하지 않도록 로딩 애니메이션을 넣는다.
- [보류] 자전거 · 킥보드 등으로 이동해 거리를 부풀리는 부정행위(어뷰징) 가능성이 있고, 이를 목격한 다른 유저가 랭킹을 불신할 수 있다 (근거: "핵심 차별점 — 구역 판정 룰"에서 랭킹을 올리려면 탄천에서 달려야 한다고 했으나 이동 수단 검증은 없음) → 팀 결정: 특정 속도 이상은 측정 불가하도록 처리한다. 다만 속도를 낮춰 타는 등 의도적인 어뷰징(킥보드 · 자동차 · 자전거 천천히 타기 등)은 막기 어렵다고 보고 이 부분은 보류한다.
- [확장-게임요소] 랭킹이 오르지 않거나 순위가 떨어졌을 때 느끼는 좌절감 · 흥미 상실로 이어질 수 있다 (근거: 문제 칸 "혼자만의 숫자 경신은 금방 지루해진다" — 반대로 랭킹 방식도 같은 지루함 · 좌절로 이어질 위험은 언급 안 됨) → 팀 결정: 다시 시작했을 때 재시작을 축하하는 보상 아이템을 제공하는 게임 요소로 확장한다.
- [확장-게임요소] 비 · 미세먼지 · 폭염 · 겨울철 등으로 탄천에서 뛰지 못하는 기간에는 랭킹에 아예 참여할 수 없어 소외감을 느낄 수 있다 (근거: "탄천 구역 외 러닝"은 랭킹 미반영 — 날씨로 인한 강제 공백 상황은 언급 안 됨) → 팀 결정: 탄천 밖에서 운동해도 개인 기록은 계속 쌓이도록 하고, 그 개인 기록을 모아 탄천의 기상악화 상황을 몰아내는 이벤트로 확장한다.
- [폐기] "이번 주 탄천 랭킹"이라는 표현처럼 주기적으로 리셋되는 랭킹을 확인하려고 하루에도 여러 번 앱을 여는 반복 확인 행동이 생길 수 있다 (근거: "3. 결과 분리 및 랭킹 반영" — "이번 주 탄천 랭킹 점수") → 팀 결정: 폐기. 접속률 · 접속 횟수가 높아지는 것은 서비스 제공자 입장에서 오히려 긍정적이라고 판단.
- [확장-게임요소] 이제 막 시작한 신규 러너가 기존 상위권과 거리 격차가 커서 진입 장벽 · 동기 저하를 느낄 수 있다 (근거: 대상 칸 "습관을 만들고 싶은 개인 러너" — 초심자 관점의 격차 문제는 언급 안 됨) → 팀 결정: 초심자의 시작을 환영하는 초심자 루트(징검다리 요소)를 하나씩 깨나가는 방식으로 확장한다.

### 2) 이 일에 얽힌, 문서에 등장하지 않는 다른 사람

- [폐기] 탄천을 관리하는 지자체(성남시) · 공원 관리기관 — Ranking Zone 경계 설정, 안전사고 발생 시 책임 소재와 관련될 수 있다 (근거: "핵심 차별점 — 구역 판정 룰"에서 특정 장소를 서비스의 핵심 기준으로 삼음) → 팀 결정: 폐기. 안전사고는 러닝 앱 사용과 관련이 없고, 구역 경계 설정도 지도(도로명주소 등) 데이터에서 가져올 예정이다.
- [폐기] 탄천에서 함께 걷거나 자전거를 타는 비러너(보행자 · 반려동물 동반자 등) — 랭킹 경쟁으로 빨리 달리려는 러너와의 충돌 · 안전 문제의 당사자가 될 수 있다 (근거: "이를 통해 탄천으로 나가 달리게 만드는 명확한 동기부여와 게임 요소를 제공한다" — 경쟁 유도가 실제 공간 이용자 안전에 미칠 영향은 언급 안 됨) → 팀 결정: 폐기. 탄천은 자전거 도로와 보행 도로가 분리되어 있고, 러너 · 비러너 간 안전 관리 문제는 앱 사용 중 상황과 관련이 없다.
- [폐기] 같은 구간을 뛰는 이웃 러너(랭킹 경쟁 상대) 자체도 서비스 안에서 서로 영향을 주고받는 이해관계자다 (근거: 불편 칸 "나와 비슷한 코스를 뛰는 이웃들과 가볍고 재미있게 경쟁" — 상대방 입장에서의 경험은 별도로 다루어지지 않음) → 팀 결정: 폐기. 서비스를 사용하지 않는 사람은 그냥 일반인일 뿐이며, "이웃 러너"는 서비스를 사용하는 사람에 한정한다.
- [확정] 위치 데이터를 다루므로 개인위치정보 처리 · 법적 신고 의무를 확인해야 하는 담당자(팀 내 [?] 또는 외부) — 위치기반서비스는 국내법상 신고 대상일 수 있다 (근거: "2. GPS 구역 판정" — GPS 이동 경로라는 개인위치정보를 수집 · 분석함) → 팀 결정: 개인정보 수집 · 이용에 관한 법령 기반 약관을 작성하고, 가입 시 동의해야 서비스를 이용할 수 있도록 한다.
- [확정] 어뷰징(부정 이동 수단 등) 신고를 접수 · 판정하는 운영자 — MVP에는 없지만 랭킹의 신뢰도를 지키는 역할이 필요할 수 있다 (근거: "핵심 차별점 — 구역 판정 룰" — 오직 장소와 개인에만 집중한다고 했으나 부정행위 검증 주체는 없음) → 팀 결정: 확정.
